# Build and preview the website

The website combines Markdown guides, Graphviz diagrams, C++ declarations and
recorded example executions. Build it locally to check content and navigation
before committing a documentation change.

## Install tools and build

You need the [simulator and example tools](prerequisites.md), plus Doxygen
and Graphviz. On Ubuntu:

```sh
sudo apt install doxygen graphviz
```

From the repository root, create the documentation environment and build the
example executables:

```sh
uv sync --frozen --extra docs
source .venv/bin/activate
cmake --preset gcc-ninja -DBUILD_TESTING=ON
cmake --build --preset gcc-ninja --parallel
python -m sphinx -n -W --keep-going -b html -D qsbit_build=build-gcc docs out/documentation-preview/html
```

For pip, create and activate `.venv`, then use
`python -m pip install -e '.[docs]'`. Numerical backend packages are not needed.
Select another simulator build with `-D qsbit_build=BUILD_DIRECTORY`.

Sphinx extracts declarations from the current headers and runs the compiled
Bell and feedback programs with scripted outcomes. It checks their event
times before writing the trace data used by the player. Generated HTML, XML
and traces stay under the output directory.

## Preview

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory out/documentation-preview/html
```

Open [localhost:8000](http://localhost:8000). Keep the server running while
you browse; press Ctrl+C to stop it.

## Edit pages and diagrams

Edit Markdown under `docs/` and add new pages to the appropriate toctree in
`index.md`. Keep tutorials focused on one complete example, task guides on
ordered steps, and reference pages on precise behavior and lookup.

Module pages describe their connections, behavior, objects, reset and errors.
They link to source and registered tests. The C++ API is generated by
Doxygen/Breathe; [interface excerpts](cpp-interfaces.md) are checked against
headers by the documentation tests.

The architecture diagram has one link per logical module. Update both
`architecture.dot` and the [module index](modules/README.md) when adding a
module. SVG links open module pages in the containing browser window.

## Edit trace displays

The player reads a trace bundle produced during the website build. Display
recorded values directly. Label calculated clock values as derived and show
the observation tick beside a last-recorded value.

Retirement records do not reveal private pipeline latches or current queue
contents. Showing those would require an observation interface in the simulator.

Source links on the rendered site use the checkout's Git revision. Links in
the Markdown files continue to open local source files.

## Run website tests

```sh
uv sync --frozen --extra docs --extra docs-test
source .venv/bin/activate
python -m playwright install chromium
cmake --preset gcc-ninja \
  -DBUILD_TESTING=ON -DQSBIT_TEST_WEBSITE=ON
cmake --build --preset gcc-ninja --parallel
ctest --test-dir build-gcc -L 'fast|website' --output-on-failure
```

The suite builds with Sphinx warnings treated as errors. Browser tests check
links, module diagrams, architecture controls and the recorded executions.
CI uploads the HTML, browser captures and test logs as workflow artifacts.
After all build and test jobs pass on `main`, CI publishes the tested HTML to
[qsbit-sim documentation](https://qsbit-org.github.io/qsbit-sim/). Pull requests
build and test the website without publishing it. To republish `main`, run the
**Build and verify** workflow from the repository Actions tab.
